# GitHub documentation example

> Updated 2026-10-20. Target release documentation; verify deployed capabilities before relying on planned features.

Illustrative workflow, not a verified Tinyfish benchmark: submit an authorized public GitHub documentation URL, inspect saved pages and warnings, then ask the connected agent a question whose answer can be checked against the source.

For GitHub repositories, the existing source parser is separate from the website crawling migration. Do not assume an arbitrary repository URL is a rendered documentation site. Use [Quickstart](quickstart.md) and verify coverage before relying on results.
